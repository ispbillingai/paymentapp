API reference

Everything is JSON over https at https://ispbillingpay.com/v1. Errors look like {"error": {"code": "...", "message": "..."}}. The message is written to be shown to a person.

Authentication

Send your secret key as Authorization: Bearer sk_live_... on every merchant request. Keys are shown once when they are created and stored only as a hash, so keep yours safe. Listener phones use their own key in the X-Device-Key header and can do one thing only: report a message.

Joining

POST/v1/merchants/register

Open to anyone, proven by a challenge. Send name, country, dial_code, currency, webhook_url and a nonce of your choosing. Before replying, we POST {"type": "challenge", "challenge": "...", "nonce": "..."} to your webhook address. Answer with {"challenge": "..."} and status 200, and only if the nonce is the one you just sent. The reply then carries your api_key and webhook_secret.

Registering an address that is already known, and passing its challenge again, replaces its keys. That is how lost keys are recovered.

Payment intents

An intent says: I expect this amount, from this number, for this reference of mine. It stays matchable for 24 hours.

POST/v1/intents

FieldMeaning
amountThe exact amount you expect, in your currency.
payer_phoneThe number the money will be sent from, in any common format. Only its last digits are compared.
payer_nameOne name of the payer. Used to confirm, never to decide on its own.
referenceYour own identifier for who this is for, such as a customer username. Required.
metadataAnything you want handed back to you.

The reply holds the intent and pay_to, the numbers your customer should send money to. Sending the same request again returns the same intent. If the money had already arrived before you asked, the intent comes back already paid.

GET/v1/intents/{id}

The intent and, once paid, its payment. Use it as a fallback if a webhook has not reached you.

POST/v1/intents/{id}/claim

For a customer who paid but was not matched. Send transaction_id from their own confirmation message and, if you can, their payer_ip so attempts can be limited. The payment must exist, equal the intent's amount, and come from the intent's number. Where the network sent no number, the name must match instead. Claiming twice returns the same result.

Payments

GET/v1/payments?status=unmatched

Payments that reached your number, newest first. Unmatched ones carry hold_reason and known_references, the references this payer has paid for before.

POST/v1/payments/{id}/assign

Take an unmatched payment for one of your references, either because a person decided or because you recognised a renewal. It succeeds once. A second attempt for a different reference is refused with already_matched.

hold_reasonMeaning
no_waiting_intentNobody was waiting to pay from this number.
known_payer_no_intentThe payer is known to you but no intent was open. Usually a renewal.
no_numberThe network left the payer number out of its message.
number_held_by_another_referenceThe number belongs to a different reference and the name did not match. A person should decide.
unreadThe message looked like a payment but could not be read with certainty. It is kept in full and never guessed at.

Listener phones

GET/v1/devices   POST/v1/devices

Create one with provider, receiving_number, receiving_name and an optional label. The reply carries the device_key once. GET /v1/me lists the providers available in your country.

POST/v1/devices/{id}/rotate   POST/v1/devices/{id}/revoke

Replace a phone's key, or stop a lost phone from reporting.

Webhooks

We POST JSON to your webhook address. Every event has an id. An event can arrive more than once, so handle each id once. Answer with any 2xx status quickly and do slow work afterwards. If you do not answer, we retry for about three days, at growing intervals.

typeWhen
payment.matchedA payment found its intent. data.intent holds the intent with its payment.
payment.unmatchedMoney arrived that could not be matched safely. data.payment and data.known_references.
payment.reversedThe network reversed a payment you were told about earlier.

Checking the signature

Each request carries X-Gateway-Signature: t=1758400000,v1=.... Compute an HMAC SHA-256 of the timestamp, a dot, and the raw request body, using your webhook secret, and compare it to v1 in constant time. Refuse anything more than five minutes old.

$expected = hash_hmac('sha256', $t . '.' . $rawBody, $webhookSecret);
$ok = hash_equals($expected, $v1) && abs(time() - $t) <= 300;
